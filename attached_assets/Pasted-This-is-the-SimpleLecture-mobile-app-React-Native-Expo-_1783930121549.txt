## BUG 3: CoursePreviewScreen missing free-preview and visibility logic

### Fix Part A: Add free chapter verification

Add a function that queries free preview chapters. Use the existing Supabase constants from `mobile/src/services/supabase.ts` (SUPABASE_URL and SUPABASE_ANON_KEY are already exported there).

```typescript
async function getFreePreviewChapterIds(courseId: string): Promise<string[]> {
  const url = `${SUPABASE_URL}/rest/v1/course_free_access_chapters?select=chapter_id&course_id=eq.${courseId}`;
  const resp = await fetch(url, {
    headers: {
      'Accept': 'application/json',
      'apikey': SUPABASE_ANON_KEY,
      'Authorization': `Bearer ${SUPABASE_ANON_KEY}`,
    },
  });
  if (!resp.ok) return [];
  const data = await resp.json();
  return data.map((row: { chapter_id: string }) => row.chapter_id);
}
```

Use this to verify that a chapter is actually in the free preview list before allowing playback. Only chapters whose IDs appear in this result should be shown as free/playable. Do not hardcode "first 3 chapters" or any fixed number.

### Fix Part B: Add topic lecture visibility filtering

Add a function to get the visibility mode:

```typescript
async function getLectureVisibilityMode(topicId: string): Promise<string> {
  const url = `${SUPABASE_URL}/rest/v1/topic_lecture_visibility?select=mode&topic_id=eq.${topicId}`;
  const resp = await fetch(url, {
    headers: {
      'Accept': 'application/json',
      'apikey': SUPABASE_ANON_KEY,
      'Authorization': `Bearer ${SUPABASE_ANON_KEY}`,
    },
  });
  if (!resp.ok) return 'both';
  const data = await resp.json();
  return data?.[0]?.mode || 'both';
}
```

Apply filtering to the AI lectures fetched for a topic:

```typescript
function filterLecturesByVisibility(lectures: AiLecturePreviewItem[], mode: string): AiLecturePreviewItem[] {
  if (mode === 'hide_marketing') return lectures.filter(l => !l.is_marketing);
  if (mode === 'hide_lecture') return lectures.filter(l => l.is_marketing);
  return lectures; // mode === 'both' or default
}
```

## BUG 4: Language switching for V4 full lectures

### File: mobile/src/screens/AILecturePlayerScreen.tsx (around line 681)

This screen fetches presentation.json and plays sections. However, for the FULL LECTURE playback (the top-level merged video, not per-section), it needs to support English/Kannada switching using the presentation's top-level fields:

- English: `presentation.vimeo_mp4_url`  
- Kannada: `presentation.kannada_vimeo_mp4_url`

The Lovable web app's resolver function works like this:

```typescript
function resolvePlaybackUrl(presentation: any, language: string): { url: string; path: string } {
  const lang = (language || 'english').toLowerCase();
  const url = lang === 'english' 
    ? presentation.vimeo_mp4_url || '' 
    : presentation[`${lang}_vimeo_mp4_url`] || '';
  const path = lang === 'english'
    ? presentation.final_video_path || ''
    : presentation[`${lang}_final_video`] || '';
  return { url, path };
}
```

If a language-switching dropdown or toggle does not already exist in the V4PlayerScreen or AILecturePlayerScreen for the full-lecture merged video, add one. When both `vimeo_mp4_url` and `kannada_vimeo_mp4_url` exist in the presentation response, show a language selector (dropdown with "English" and "Kannada"). When the user switches:
1. Pause the current video
2. Replace the video source with the new language's MP4 URL
3. Resume playback
4. Do NOT create a second player instance

If only one language URL exists, do not show the language selector.
