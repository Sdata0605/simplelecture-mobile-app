# 1. Feature definition

This feature is an **AI-generated study-notes reader**.

It is not:

* a user-authored notes editor;
* personal annotations;
* highlights;
* handwritten notes;
* voice notes;
* a student notes database;
* a note-sync system.

The study notes are projected dynamically from the latest published and completed AI lecture for the selected topic.

The source is:

```text
video_generation_jobs.presentation_json
```

joined to the topic through:

```text
ai_assistant_documents.topic_id
```

The core flow must be:

```text
Student opens a topic
→ opens the Notes tab
→ app loads the latest published/completed AI lecture job
→ reads presentation_json.sections
→ converts the lecture sections into study-note pages
→ displays the notes in a native book-style reader
→ optionally displays important/practice questions
→ optionally generates additional practice questions through the existing Supabase Edge Function
```

# 3. Natural interaction requirements

## Next page

For a forward page turn:

1. The current page begins at its normal flat position.
2. The learner swipes or drags from right to left.
3. The page visually lifts from the outer right edge.
4. The right edge follows the finger.
5. The page rotates and bends toward the book spine.
6. A moving shadow appears beneath the turning page.
7. The reverse side of the sheet becomes visible after the midpoint.
8. The next page is visible underneath.
9. Releasing after the completion threshold finishes the page turn.
10. Releasing before the threshold returns the page naturally.

## Previous page

For a backward page turn:

1. The previous page appears from the left side.
2. The learner drags from left to right.
3. The page follows the finger.
4. Shadows and highlights reverse direction correctly.
5. The page either completes or settles back based on progress and velocity.

## Gesture expectations

Support:

* slow drag;
* quick swipe;
* interrupted drag;
* release before halfway;
* release after halfway;
* velocity-based completion;
* Previous and Next buttons;
* programmatic page jump from Contents.

The animation must follow the finger continuously. It must not wait until the gesture ends before starting.

# 4. Gesture recognition

Use Gesture Handler and Reanimated worklets where available.

The page flip must distinguish horizontal page-turn intent from vertical content scrolling.

Recommended intent detection:

```typescript
const isHorizontalIntent =
  Math.abs(translationX) > Math.abs(translationY) * 1.2;
```

Do not begin a page flip for a mostly vertical gesture.

Use a small activation threshold so normal taps are not treated as page turns.

Suggested range:

```typescript
const ACTIVE_OFFSET_X = 12;
const FAIL_OFFSET_Y = 18;
```

Adapt these values after testing.

## Vertical scrolling conflict

* vertical scrolling must continue to work normally;
* diagonal gestures must not accidentally flip pages;
* a horizontal gesture must intentionally claim the page turn;
* vertical scroll position must not reset unexpectedly;

Use Gesture Handler relationships such as:

* simultaneous gestures;
* race gestures;
* manual activation;
* directional thresholds;

depending on the existing architecture.

Do not solve this by disabling vertical scrolling.

# 5. Animation progress model

```typescript
const flipProgress = useSharedValue(0);
```

```text

```

For backward movement, either use:

```text

```

Clamp progress strictly between 0 and 1.

The gesture should update progress according to page width:

```typescript
flipProgress.value = clamp(
  Math.abs(translationX) / pageWidth,
  0,

```

The exact transform must be direction-aware.

Do not update React state on every gesture frame.

Use Reanimated shared values during movement.

# 6. Completion physics

A page turn should complete when either:

* drag progress passes an appropriate threshold; or
* release velocity strongly indicates the intended direction.

Suggested starting values:

```typescript
const COMPLETION_PROGRESS = 0.35;
const COMPLETION_VELOCITY = 650;
```

Tune these based on real device testing.

## Completed turn

Animate to `1` using a natural timing or spring.

Suggested duration range:

```text
260–420 milliseconds
```

The duration may be shorter when release velocity is high.

After completion:

1. update the page index;
2. reset the shared progress;
3. prepare the next adjacent pages;
4. restore gesture input.

## Cancelled turn

Animate back to `0` using a soft spring.

Avoid:

* excessive bounce;
* elastic overshoot;
* slow floating;
* sudden snapping.

Suggested spring behaviour:

```typescript
withSpring(0, {
  damping: 22,
  stiffness: 220,
  mass: 0.8,
  overshootClamping: true,
});
```

Treat these values as starting points and tune them visually.

```typescript
  { perspective: 1200 },
  { translateX: ... },
  { rotateY: ... },
  { translateX: ... },
]
```

Tune perspective by device width.

Suggested range:

```text
900–1600
```

The rotation origin must feel like the page is turning around the book spine, not around its centre.

React Native does not provide a direct transform-origin API on every target, so emulate the origin through paired `translateX` operations.

## Front and rear faces

Use two layered page faces:

* front face: the current page;
* rear face: the appropriate reverse/destination content or a paper-toned back surface.

Set:

```typescript
backfaceVisibility: 'hidden'
```

Ensure the back content is not accidentally mirrored.

At the midpoint, visibility must transition cleanly with no flicker.

## Page curvature

When Skia is already available, use it only to enhance:

* curved page clipping;
* curl gradient;
* moving fold;
* page deformation;
* realistic shadow.

When Skia is unavailable, simulate curvature using 3–5 narrow vertical page segments.

Each segment may rotate by a slightly different amount based on:

* flip progress;
* distance from the outer edge;
* distance from the spine.

This creates a progressive bend rather than one rigid rectangular rotation.

Do not create too many segments, because Markdown and image content must not be rendered repeatedly in every segment.

A safe fallback is:

* one content snapshot/layer;
* one or two overlay gradients;
* 3D rotation;
* edge distortion;
* dynamic shadow.

Prioritize stability over unnecessary complexity.

---

# 8. Shadows and lighting

Use dynamic lighting to make the page feel physical.

Include:

## Cast shadow

A soft shadow beneath the turning page.

It should:

* become stronger early in the turn;
* move toward the spine;
* soften near completion;
* reverse correctly for backward turns.

## Fold shadow

A narrow darker band near the fold.

Its position must follow the animated fold.

## Edge highlight

Add a subtle bright highlight along the curved outer edge.

## Spine shadow

Add a persistent subtle shadow near the centre/spine of the book.

Avoid:

* pure black heavy shadows;
* extreme blur;
* excessive opacity;
* neon effects;
* shadows that remain after the page settles.

All lighting must match the existing Notes theme.

---

# 9. Paper appearance

Create a premium paper feel without harming readability.

Use existing theme tokens when available.

Suggested visual treatment:

* warm off-white page;
* extremely subtle paper gradient;
* soft page border;
* rounded outer corners;
* low-intensity texture only if it is lightweight;
* readable dark ink;
* distinct but restrained callout colours.

Do not use a large raster texture on every page.

Do not reduce text contrast.

Do not place animation overlays above interactive content when the page is idle.

---

# 10. Phone layout

On phones:

* display one page at a time;
* the page should use nearly the full available width;
* preserve safe-area padding;
* allow vertical content scrolling;
* horizontal swipe flips the page;
* show page count clearly;
* keep Previous and Next buttons accessible;
* avoid tiny text.

Forward turns should visually originate from the right edge.

Backward turns should visually originate from the left edge.

At the first page, backward dragging should show subtle resistance but must not reveal a blank page.

At the last page, forward dragging should show subtle resistance but must not reveal a blank page.

Do not loop from the last page to the first unless the product already requires looping.

---

# 11. Tablet and two-page spread

On larger tablets:

* display a realistic left/right two-page spread where space permits;
* add a centre gutter/spine;
* preserve correct logical page order;
* flip the right page toward the left when moving forward;
* reveal the next spread beneath;
* flip the left page toward the right when moving backward.

Do not render the same page on both sides.

Correctly handle:

* odd number of pages;
* first cover/page;
* final unpaired page;
* orientation change;
* split-screen resizing.

When the layout changes between phone and tablet, preserve the learner’s nearest logical page rather than resetting to page one.

---

# 12. Adjacent-page rendering

For performance, mount only the pages needed for the current interaction:

* previous page/spread;
* current page/spread;
* next page/spread;
* active turning layer.

Do not render every note page simultaneously.

Preload adjacent images where the existing image system supports it.

The underlying next page must already be visible before the top page begins turning so no blank flash appears.

Use stable page keys.

Do not recreate heavy Markdown trees on every animation frame.

Memoize page content where appropriate.

---

# 13. Interaction locking

While a page is settling:

* prevent another page-turn gesture;
* prevent double index updates;
* prevent Previous/Next button spam;
* prevent Contents jumps from corrupting the state;
* keep the UI responsive.

After completion or cancellation, unlock interaction.

Never leave the pager permanently locked if an animation is interrupted or a component unmounts.

Cancel active animations safely on unmount.

---

# 14. Buttons and programmatic navigation

Previous and Next buttons must trigger the same animation as a gesture.

Do not instantly replace the page when these buttons are pressed.

Contents navigation may use:

* a shorter page-turn animation for nearby pages;
* a controlled crossfade for distant jumps;
* an immediate jump only when reduced motion is enabled.

Do not animate through every intermediate page when jumping from page 2 to page 40.

After a Contents jump, the page index and page indicator must remain correct.

---

# 15. Accessibility and reduced motion

Respect the platform’s reduced-motion preference.

When reduced motion is enabled:

* disable the 3D flip;
* use a short fade or immediate page replacement;
* keep navigation fully functional.

Add accessible labels for:

* Previous page;
* Next page;
* current page number;
* Contents;
* page content.

Do not make swipe the only navigation method.

Maintain touch targets of approximately 44×44 points or larger.

Do not use animation that makes text unreadable for prolonged periods.

---

# 16. Performance requirements

Target smooth rendering on normal mid-range Android devices.

The animation should aim for:

```text
60 FPS on supported devices
```

Requirements:

* run gesture and transform work on the UI thread;
* avoid React state changes during every animation frame;
* avoid JS timers for the flip;
* avoid repeated JSON parsing;
* avoid repeated pagination during a flip;
* avoid rendering all pages;
* avoid large shadow bitmaps;
* avoid console logging per frame;
* avoid unnecessary layout measurements;
* cache page dimensions;
* use `runOnJS` only when committing the final page index or announcing accessibility changes.

Test with pages containing:

* long narration;
* Markdown;
* formulas;
* images;
* bullets;
* questions.

The animation must remain smooth when the page content is complex.

---

# 17. Orientation and responsive behaviour

Handle:

* portrait;
* landscape;
* phone;
* tablet;
* split screen;
* dynamic dimensions;
* font scaling.

When dimensions change:

1. finish or cancel any active flip safely;
2. recalculate the page width;
3. preserve the logical current page;
4. reset animation transforms;
5. prevent a blank intermediate state.

Do not hardcode a single screen size.

---

# 18. Error resilience

The page flip must not crash when:

* pages array is empty;
* there is only one page;
* current page index is invalid;
* an image fails;
* Markdown rendering fails;
* orientation changes during a flip;
* the component unmounts during an animation;
* the learner rapidly presses Next;
* the learner reverses drag direction;
* the learner starts a vertical scroll;
* reduced motion changes.

Clamp all page indexes.

Show the existing Notes empty/error state when no pages exist.

---
